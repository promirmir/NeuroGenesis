# NeuroGenesis — permanent mission and technical acceptance contract

**Official public credit: Miron przy pomocy AI.**
**Priority:** user-directed effort toward a powerful, novel, scalable, continuously
learning neural AI with a local Windows desktop. The scope, constraints and
measurements in this file survive every chat interruption.

## The intended product

Create a serious experimental artificial brain rather than a fixed FAQ or a
pretrained chatbot disguised as a new architecture. Its components must learn
useful representations and temporal context, maintain long-lived experiences,
self-assess and self-repair with controlled evidence, use online public data as
untrusted sensory input, and give the operator an intelligible live view of its
behavior. The app should be one-click Windows EXE, with conversation, provenance
and brain/compute visualization. GPU/CUDA and later voluntary multi-device
scaling are part of the performance plan.

The user wants an ambitious scientific breakthrough. **That is a research
aspiration, not an achievement or a guarantee.** Human brain mathematical
similarity requires concrete equations, falsifiable physiology-inspired
mechanisms, data and measured functionality. No evidence currently establishes
consciousness, full human-neuron emulation, general intelligence or competitive
frontier language reasoning.

## Priority order

1. **Foundation computation**: ordered language input, learned multi-timescale
   representations, a genuinely trained predictive model and long context,
   with measured CPU/GPU cost. The old small spiking LIF neural network is
   a reference component and may become a proven, coupled neurodynamic module;
   it must not be misrepresented as a large capable brain.
2. **Lifelong learning**: local streaming/self-supervision, loss and retention
   measurements, episodic semantic consolidation, prospective independent
   tests, rollback and resource/permission budgets. Never use one toy metric
   to claim meaning, reasoning or automatic intellectual progress.
3. **Internet as perception**: operator-approved HTTPS read-only sources,
   provenance and SHA-256, deny SSRF/private IPs/redirects/code execution.
   Refresh approved sources at a bounded rate; never read, execute, trust or
   follow commands in downloaded documents. Promote external facts to
   conclusions only with verification and source calibration.
4. **Useful desktop**: chat, opt-in teaching, current model and GPU state,
   real-time graph of neural dynamics, events, learning metrics and source
   provenance. Opening the app must not start unbounded training, external
   data fetching, use of other devices or cloud charges.
5. **Neurobiology-inspired mechanisms**: LIF/spiking dynamics, synaptic
   plasticity, growth/pruning, multiscale state, homeostasis, sleep-like
   consolidation, fault recovery and developmental adaptation. Scientific
   ablations must show whether each mechanism is useful versus equal-compute
   controls.
6. **Verified distribution**: green Linux Python 3.11–3.13, dedicated REAL
   PyTorch foundation CI, Windows 64-bit standalone EXE regression + offline
   smoke test, GitHub Releases artifact and checksum. Keep old SQLite memory
   and trained checkpoints private and upgrade-compatible.

## Continuous quality gates

- Each improvement needs a **held-out**, declared task and a simpler matched
  baseline; measure errors, memory, runtime, hardware, confidence and failures.
- Prior data must never be silently erased or rewritten. Failed upgrades
  should preserve an intact recoverable private checkpoint.
- Do not hardcode the private initiator's surname or personal contact
  anywhere public. Alias in Git author names is safe; Git email visibility was
  explicitly accepted. Public display credit stays exactly as written above.
- Save state in AGENTS.md, docs/PROJECT_STATE.md and docs/DEVELOPMENT_LOG.md,
  cite exact PR/commit and actual CI results, and resume from GitHub rather
  than guessing from chat context. Do not make unverified release claims.
- Code can be developed through explicitly requested chat turns or scheduled
  agent tasks if supported; an open desktop/ChatGPT tab by itself **does not**
  authorize or technically create continuous background work.

## Versions and research boundaries

- v0.5.6: verified standalone Windows GUI, LIF+SQLite, manually taught Q/A,
  opt-in bounded self-tuning. Genuine chat semantics and internet OFF.
- Foundation Brain v1 (PR #19): merged PyTorch GRU multi-timescale predictive
  **research backbone**, actual CPU tests pass, not yet trained on adequate
  general text, no demonstrated semantic cognition or GPU benchmark.
- Next candidate: opt-in pinned HTTPS perception integrated with the old LIF
  brain as an experimental sensory interface. The new GPU foundation is not
  yet integrated with this acquisition path. Data provenance does not equal
  accuracy and a better sensory feed alone does not yield intelligence.

This file is the product requirement baseline. Any subsequent implementation
must work toward this whole system rather than celebrating disconnected toy
features as if they completed the objective.
